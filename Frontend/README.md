# SKB-CRM — Frontend (سایت + پروکسی API)

این سرویس دو کار می‌کند:
1. فایل‌های استاتیک سایت (`HTML/CSS/JS`) را سرو می‌کند.
2. `/api/*` و `/uploads/*` را به بک‌اند (Express روی پورت ۵۰۰۰) **پروکسی** می‌کند تا
   مرورگر همه‌چیز را از یک مبدأ (same-origin) بگیرد.

---

## اجرا

```bat
:: ریشهٔ پروژه (توصیه‌شده — خودش API_URL و PROXY_STRICT را ست می‌کند و در حلقه ری‌استارت می‌شود)
start-frontend.bat

:: یا مستقیم
cd Frontend
npm start
```

متغیرهای محیطی مهم:

| متغیر | پیش‌فرض | توضیح |
|---|---|---|
| `PORT` | `3000` | پورت سایت |
| `API_URL` | `http://127.0.0.1:5000/api` | آدرس بک‌اند |
| `PROXY_STRICT` | `false` | اگر `true` باشد **فقط** `API_URL` استفاده می‌شود (بدون fallback پنهان به پورت ۵۰۰۰/آی‌پی دیگر) |
| `PROXY_TIMEOUT_MS` | `600000` | مهلت پروکسی (برای آپلود ویدیو تا ۵۰۰MB) |

> ⚠️ نکتهٔ مهم: اگر `PROXY_STRICT=false` باشد و بک‌اند اصلی خواب باشد، درخواست‌ها
> بی‌صدا به کاندیدهای بعدی می‌روند و ممکن است تا دقایق معلق بمانند. روی سرور واقعی
> همیشه `PROXY_STRICT=true` بگذار (در `start-frontend.bat` ست شده است).

## کش و نسخه‌دهی دارایی‌ها

هنگام سرو هر صفحه، به آدرس همهٔ `JS/CSS`های محلی یک `?v=<ASSET_VERSION>` اضافه
می‌شود (نسخه از جدیدترین زمان تغییر فایل‌ها ساخته می‌شود) — بدون تغییر دستی فایل‌های HTML.

| نوع فایل | هدر کش |
|---|---|
| `JS/CSS` با `?v=` | `public, max-age=31536000, immutable` (یک‌ساله، بدون درخواست دوباره) |
| `JS/CSS` بدون نسخه (importهای داخلی) | `private, max-age=60, must-revalidate` (+ ETag → پاسخ ۳۰۴ سبک) |
| تصاویر/فونت‌ها | `public, max-age=86400` |
| صفحات HTML | `no-cache` (همیشه تازه، با ETag) |

**نتیجهٔ عملی:** بعد از هر تغییر کد، فقط سرور را ری‌استارت کن؛ نسخهٔ آدرس‌ها عوض
می‌شود و مرورگر کاربران خودش فایل‌های جدید را می‌گیرد (نیازی به «کش را پاک کن» نیست).

## دستورها

```bat
npm start          :: اجرای سرور
npm run lint       :: بررسی کد مرورگر (ESLint) — باید ۰ error و ۰ warning بدهد
npm run test:cache :: تست نسخه‌دهی/کش/۳۰۴ (بدون نیاز به بک‌اند یا دیتابیس)
```

`npm run lint` خطاهای واقعی مرورگر را می‌گیرد (مثلاً استفاده از `Buffer` که در مرورگر
وجود ندارد، یا متغیر تعریف‌نشده). اگر خواستی هشداری را آگاهانه نگه داری، از
`// eslint-disable-next-line <rule>` با توضیح استفاده کن.

## نکات امنیتی مرتبط با این سرویس

- **`/uploads` عمومی است** (چون در `<img>/<video>/<iframe>` استفاده می‌شود و مرورگر
  روی این درخواست‌ها توکن نمی‌فرستد). برای همین بک‌اند این سخت‌گیری‌ها را اعمال می‌کند:
  پسوندهای اسکریپتی/اجرایی (`html`, `js`, `svg`, `exe`, …) هرگز سرو نمی‌شوند (۴۰۴)،
  `X-Content-Type-Options: nosniff` همیشه ست می‌شود و فایل‌های غیرتصویری با
  `Content-Disposition: attachment` (دانلود) فرستاده می‌شوند.
- محتوای آپلودشده **هرگز داخل مبدأ سایت اجرا نمی‌شود** (جلوگیری از سرقت توکن از localStorage).
- اگر روزی نوع فایل جدیدی لازم شد که در لیست مجاز نیست، در `Backend/server.js`
  مقدار `UPLOADS_INLINE_EXT` را به‌روز کن (نه اینکه کل محافظ را برداری).
- پنجره‌های چاپ/گزارش با `sanitizeHtmlDocument()` پاک‌سازی می‌شوند (فایل
  `src/core/utils/string.utils.js`) چون هم‌مبدأ با سایت‌اند و به `opener` دسترسی دارند.
